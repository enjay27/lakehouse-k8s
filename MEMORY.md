Three fixes per feedback: (1) **Query tightened** — `loggerName: io.agroal.pool` moved from a should-option to a mandatory `must`; should-clauses switched to `match_phrase` on only proven substrings (`connection refused`, `too many clients already` — the real Case B signal, a verbatim relayed PostgreSQL FATAL string, not the guessed generic Agroal timeout message; `broken pipe` kept as documented-not-yet-observed). Rationale: this is infra-owned (not fixed in Polaris app code), so whoever's paged needs an explicit all-clear. (3) **Vert.x blocked-thread warnings explicitly excluded** — real signal in the live run, but not treated as "DB unavailable" (client already sees the failure, can retry); `matches_db_pool_signal()` added as a pure-Python check, asserted in a new NB15 cell against the real captured blocked-thread message. `src/opensearch_alert_provisioner.py`: `ALERT_TRIGGER_NAME`/`RESOLVED_TRIGGER_NAME` replace the old single `TRIGGER_NAME`; new `trigger_fired(result, name)` looks up by name (trigger_results is keyed by ID); notebooks' assertion cells updated to match. `doc-db-connection-pool-logs.md` and the guide doc updated with real Case B logs (previously an unverified guess) and the new design.
