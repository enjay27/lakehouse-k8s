# The Big Merge — `local-k8s` + `polaris-learning` -> `lakehouse-k8s`

**Date:** 2026-09-21 · **Status:** done, unverified (no gate could be run from this session)

---

## 1. What happened

Two repositories became one. 554 tracked files at `HEAD` were relocated into a single tree
organised by *kind of artifact* rather than by repository of origin. 34 files were dropped by
explicit decision. Nothing else changed: no file's contents were edited, no configuration was
touched, no cluster was contacted.

Both pre-merge histories are preserved **in this repository**, on refs of their own:

```bash
git log archive/local-k8s          # 212 commits, 2026-07-09 .. 2026-09-21
git log archive/polaris-learning   # 223 commits, 2026-06-02 .. 2026-09-21
git log --all --grep='denominator' # searches the archives as well as main
git log --all -S'fb_values_path'   # pickaxe across every ref
```

Immutable tags pin the same two points: `v-archive/local-k8s-2026-09-21` and
`v-archive/polaris-learning-2026-09-21`. Anything reachable from a branch or a tag is never
pruned by `gc`, so all 435 commits and their ~7,000 lines of commit body survive.

---

## 2. Why

These were never two projects. They were two halves of one system with a filesystem path as the
joint, and the joint leaked.

**The dependency was declared, in writing, in both directions.**
`local-k8s/.memory/goal.md` opened with *"Everything here exists to serve one downstream
consumer: the `polaris-learning` test suite."* `polaris-learning/CLAUDE.md` named its schema
authority as `$HOME/hynix/local-k8s/postgresql/schema/schema_v3.sql` — a policy statement in one
repo about a file in the other. 251 lines in `polaris-learning` mentioned `local-k8s`; 67 went
the other way.

**The coupling was executable, not just documentary.**
`reset_realm.sh` defaulted `SCHEMA_SQL` and `BOOTSTRAP_SQL` to paths inside the other repo.
`src/config/local.yaml` set `fb_values_path` to `~/hynix/local-k8s/logging/fb-values.yaml`, and
`src/log_coverage.py` called that file *"the ONE"* source of the retention policy.
`test_log_coverage.py:162` skipped a test outright with the message
*"local-k8s/logging/fb-values.yaml not reachable from here"* — a repo boundary silently
degrading test coverage.

**And it was going to get worse.** `log-coverage/SCENARIO-logging-test.md` (status: PROPOSED)
designed a `CONTRACT_VERSION`-gated module import so that `local-k8s` could call
`polaris-learning/src/make_traffic.py`. That is a versioned inter-repo API invented to solve a
problem the repo boundary created. Merging turns it into an ordinary import.

**What the boundary actually cost, measured in the repos' own history:**

| drift | one repo | the other | gap |
|---|---|---|---|
| Pgpool-II, not PgBouncer | corrected 2026-08-18 | corrected 2026-08-20 | 2 days |
| Polaris 1.6.0 deployed | 2026-09-18 | `CLAUDE.md` said `v1.3.0-incubating` until 2026-09-21 | 3 days |
| `fb-values.yaml` release uninstalled | 2026-09-18, marked "history, not configuration" | still the configured `fb_values_path` | unresolved — see M3 |

Same fact, two files, two corrections, days apart. One repo makes that one commit.

## 3. Decisions taken

| decision | choice | by |
|---|---|---|
| merge strategy | fresh-root `main` + archive refs, not `--allow-unrelated-histories` | Kade |
| repository name | `lakehouse-k8s` | Kade |
| `src/` and `tests/` | both at repo root | Kade (recommended) |
| jupytext pairing | follow-up commit, not this one | Kade (recommended) |
| dead/duplicate files | dropped in the merge | Kade |
| subdirectory naming | `charts/ releases/ logging/ ...` by artifact kind | Kade's structure, gaps filled |

### Why fresh-root rather than a real merge

A real `--allow-unrelated-histories` merge would additionally give `git blame` and `git bisect`
across the seam. It was not chosen, and the trade is understood: **crossing the seam on `main`
now takes two steps instead of one** (`git log --all -S`, or check out the archive ref).

The choice is reversible in the direction that matters. Because the archive refs are real
commits in this repository, the histories can be joined at any later date without rewriting
anything:

```bash
git merge --allow-unrelated-histories archive/local-k8s archive/polaris-learning
```

The reverse is not true, which is why this was the safer place to start.

## 4. The structure, and why each directory exists

```
charts/       LOCAL charts — this repo is the source of truth (minio, polaris, postgresql)
releases/     VALUES-ONLY overlays on upstream charts (8 services)
logging/      the audit-logging domain: SPEC, guides, opensearch/ templates, Lua candidates, step scripts
schema/       Polaris DDL — schema_v3.sql is the ASF-shipped file and the authority
src/          reusable Python modules (26)
tests/        pytest suite (21 modules)
notebooks/    per-domain test notebooks (10 domains, 66 notebooks total with diagnostics/)
diagnostics/  inspect notebooks + ladders/ (high-rigor sweeps) + outputs/ (banked vs captures)
runbooks/     deterministic operational runs
archive/      superseded docs, plus both pre-merge CLAUDE.md and MEMORY.md
docs/         this file
```

Four directories were added to the structure as originally sketched, because 554 files would not
fit it:

- **`releases/`** — eight directories (`airflow argo datahub fluent-bit jupyter kafka
  schema-registry spark`) are values files aimed at *upstream* charts, not charts.
  `repository-map.md` made that distinction load-bearing: a file under `charts/` changes what
  ships, a file under `releases/` is an overlay on someone else's chart. Folding them together
  would erase the only axis that tells you which is which.
- **`logging/`** — 73 files with no home in the sketch: the authoritative
  `SPEC-polaris-audit-logging.ko.md`, 34 markdown documents, 12 shell scripts, 6 Python, 6 Lua
  harnesses, 5 OpenSearch template/ISM JSONs, a drawio. It is a domain, not a chart and not a
  notebook.
- **`schema/`** — the Polaris DDL is referenced *across* both halves (the suite's schema policy
  names it as authority), so burying it inside `charts/postgresql/` would make it look
  chart-internal.
- **`tests/`** — 21 `test_*.py` modules were loose at the old repo root.

And one label was corrected: `diagnostics/outputs/` was described as "git-ignored", but
`runs/` (62 JSON), `baselines/` (3) and `reports/` (xlsx, png, md) are tracked **on purpose** —
`run_manifest.py`: *the manifest carries values, the live cluster carries truth, never one
without the other.* Only the capture directories are disposable. Hence the split into
`outputs/banked/` (tracked) and `outputs/captures/` (ignored).

### `src/` at the root is a security decision, not a taste decision

The secrets ignore is `src/config/*.yaml` with `!common.yaml` and `!*.example.yaml`. A gitignore
pattern containing a slash is **anchored to its own file's directory**. Keeping `src/` at the
repository root keeps that pattern matching unchanged. Moving `src/` under `notebooks/` would
have de-anchored it, and `src/config/local.yaml` — which holds `POLARIS_ROOT_SECRET` — would have
become trackable.

The gate was run before the commit, in both directions:

```
src/config/local.yaml                            IGNORED ok
src/config/dev.yaml                              IGNORED ok
src/config/prod.yaml                             IGNORED ok
diagnostics/ladders/log-coverage/spec/*.yml      IGNORED ok
diagnostics/outputs/captures/*                   IGNORED ok
notebooks/rbac/lib/*                             IGNORED ok
src/config/common.yaml                           trackable ok
src/config/local.example.yaml                    trackable ok
.../log-coverage/spec/inventory.json             trackable ok
```

## 8. What was NOT carried across

The merge snapshotted **`HEAD` only**, deliberately, so that no uncommitted working-tree content
could reach the new repository. These files had uncommitted changes at merge time and **are not
here**; they are untouched in the original directories:

- `local-k8s`: 3 untracked files under `Claude outputs/`.
- `polaris-learning`: `availability/polaris_availability_test.ipynb` (**contains the deliberately
  uncommitted principal credential — this is why HEAD-only was chosen**),
  `src/log_coverage.py`, `test_iceberg_rest.py`, `test_vlogs.py`,
  `log-coverage/polaris_api_traffic_v1.ipynb`,
  `diagnostics/api-sql-profile/_verify_cache_column.py`,
  `diagnostics/api-sql-profile/render_explain_workbook.py`.

**Port these deliberately.** Six of them are real in-flight work.
