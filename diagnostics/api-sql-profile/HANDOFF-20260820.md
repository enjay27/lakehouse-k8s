## What changed this session

**Toolchain.** `black`, `isort` and `pytest` were mandated by `CLAUDE.md` but had
never been declared as dependencies, so the DoD was unrunnable and every "tests pass"
claim in `MEMORY.md` came from a sandbox. Now in `[dependency-groups] dev`.

**19 stale tests fixed** (commit `3f984cb`) — red for weeks, invisible because pytest
was not installed. All were test rot, no source bugs. Plus one src change: in `seed()`
the `require_local` safety guard now runs **before** argument validation, so a seed
aimed at a company cluster reports that rather than a missing bucket.

**Helpers promoted** to `src/api_trace.py`: `timeit`, `explain`, `explain_n`,
`find_capture_dir`, `EXPLAIN_N`, `NO_LOAD_BALANCE`. 01 and 02 repointed. The two
copies of the capture-dir resolver had already drifted; there is now one.

**The cache column was fixed.** `TraceRecord.cache_verdict` could only ever return
MISS on this build, so `cache: MISS` on all 43 APIs was never evidence. Replaced by
`cache_shape` (WARM/MIXED/COLD/N-A) and `batched_share`; `to_row()` no longer emits
the dead column. Verified against the real capture: 734/844 requests (87%) contain a
batched revalidation, median share 0.33, and **zero WARM** — no request is served
purely by batching, because path resolution must load its first entity by name.

**01's preflight no longer guesses.** It scanned the log's tail for
`DatasourceOperations` and inferred logging was off — unsound both ways (SQL DEBUG is
~0.75% of lines, so a healthy capture fails; and a stale tail passes while logging is
genuinely off). It now issues one authenticated call and checks for *its* statements.

**Reports carry full text.** SQL was truncated at 180 chars *and* flattened into
markdown table cells — 486 of 511 statements (95%) were being mangled, removing the
WHERE clause from exactly the statements worth reading. Now fenced ```sql blocks with
parameters. `detail` was cut at 140 chars mid-word. Added a **statement catalogue**
surfacing four fields the audit already collected and discarded: issuing APIs, seq/index
scan counts, rows discarded by filter, EXPLAIN errors.

**`check_hypotheses` had two defects**, both found only because the report started
rendering its evidence:
1. It matched predicate columns against the **whole statement**, so a column in the
   SELECT list counted as constrained. Three irrelevant statements were voting on
   `grant_records_by_grantee`. Now matches the WHERE clause via a shared
   `api_trace.where_clause()`, plus an optional `verb` per hypothesis.
2. It reported **REFUTED** once our own index existed — telling the reader the index
   was unnecessary, in the same directory as a report measuring 188x for adding it.
   New **REMEDIED** status distinguishes "our fix is installed" from "the claim was
   wrong"; REFUTED now requires a **named pre-existing** index, and an unattributable
   index scan is INCONCLUSIVE rather than a guess.

## Rules worth not relearning

1. **Classify on the WHERE clause**, never the projection or the whole statement.
2. **Render the evidence.** Both `check_hypotheses` bugs were invisible until the
   report printed the SQL each verdict came from.
3. **Turn statement logging off before timing** — a 4.6x spread on an identical plan.
   01 is exempt: it measures shape, not latency, and needs DEBUG on.
4. **Restart the kernel after any `src/` edit.**
5. **EXPLAIN on the PRIMARY** — `/*NO LOAD BALANCE*/`, `pg_is_in_recovery()` False.
6. **Never let your own remedy read as a refutation.** See REMEDIED.
